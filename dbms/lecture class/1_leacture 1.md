## Course Format, Practical Work, and Assessment Rules

Practical classes will focus on completing database exercises, while theory classes will later include practical implementation as well.

**Practical files** must be maintained as soft copies; hard-copy files are not required.

Completed practicals will become the foundation for a project.

Project work will be completed in groups to develop teamwork and produce a working project.

**Assessment structure**:

One assignment will be given for the entire semester.

Three or four open quizzes may be conducted as units are completed.

**Classroom phone rule**: Phones must remain silent, upside down, and unused by students so that notifications do not interrupt concentration.

## DBMS Foundations: Data, Schemas, Entities, and Relationships

The syllabus contains four units, with the first one and a half units primarily covering theory.

Fundamental topics include:

Definitions of data, databases, and Database Management Systems

Types of data models

Database users and their roles

Views, instances, and schemas

**Entity–Relationship concepts** connect DBMS terminology with C++ object-oriented programming:

Objects in programming are treated as entities in DBMS.

Teacher and student can be represented as entities and tables.

A teacher–student relationship represents teaching and learning.

One teacher may teach many students, while many students may be taught by one teacher, forming a one-to-many relationship.

Tables, their properties, and basic queries will be taught so students can create tables and communicate with databases.

A school-result website was used as an example: entering a roll number and submitting it retrieves the student’s name, subjects, marks, and result from the database.

Foundation of Data Science was identified as a prerequisite. It provides mathematical preparation and introduces tools or languages such as Power BI, R, and SQL before DBMS and the later MongoDB course.

## Normalization, Missing Data, Joins, and Advanced DBMS Topics

**Normalization** organizes large amounts of data so that processing remains reliable and individual missing records do not block an entire result set.

A missing answer sheet with attendance recorded was used as an example:

The complete class result should not be stopped because of one missing student record.

The result may be marked as “result awaited” or processed using an appropriate replacement value.

Proxy marks are not acceptable; average marks may be used where appropriate.

`NULL` should not be left as an undefined value in the discussed cases.

“Not applicable” should be used when a field or subject genuinely does not apply.

Normal forms mentioned included First Normal Form, Second Normal Form, BCNF, Fourth Normal Form, and Fifth Normal Form. The instructor indicated that only selected forms, especially First, Second, and BCNF, would receive major practical attention.

**Joins** allow queries to work with two tables simultaneously, such as combining teacher and student information.

Unit 3 is primarily practical and will cover implementation of normalization and transactions.

Unit 4 introduces concurrency control, transaction control, deadlocks, and selected advanced DBMS concepts.

Completing the practical syllabus quickly will allow the class to move toward more advanced DBMS material.

## Course Resources, Relational DBMS, and Class Logistics

The detailed syllabus will be uploaded to the institution’s DG platform.

Notes and PowerPoint material may be provided, but students were encouraged to create their own notes.

PowerPoint files are expected to contain mainly diagrams and supporting material rather than the complete lecture explanation, and examination questions will not necessarily come directly from the slides.

Laptops are preferred for classwork, especially because the schedule is currently being reshuffled.

Classes may temporarily be held in different locations, including the E Block, ARBR, or the E Block top floor.

The current DBMS course is relational rather than NoSQL-based.

MongoDB will be taught in the next semester and was contrasted with the current course:

MongoDB uses document-based storage.

Relational DBMS requires tables and schemas.

MongoDB was described as easier for document-oriented data and useful when fast response is important.

SQL is suitable for structured, similar data such as marks and student results.

Joins and normalization are central to relational databases but are not the primary focus in MongoDB.

## MySQL Workbench, Individual Submissions, and Database Selection

The first laboratory session will use MySQL Workbench.

Students were instructed to bring laptops, whether running Windows or macOS.

Students without laptops can use available laboratory desktops.

Every student must create a personal folder and upload their own practical files.

Copying one student’s work and submitting identical files for the entire group is not acceptable because individual practical work will be checked.

**Database-selection examples**:

SQL was associated with structured text and numerical data, such as examination results.

MongoDB was associated with varied or unstructured data and document-based applications.

Oracle Enterprise Edition was presented as a paid, enterprise-oriented system used by large organizations requiring stronger security.

SQL was described as an open-source option for smaller organizations with structured data and less demanding security requirements.

SAP was discussed as a highly secure backbone for large financial institutions and organizations with multiple branches or databases, allowing data to be queried or combined across systems.

Banking institutions, large companies, and cement plants such as Ambuja Cement were cited as examples of enterprise environments using systems such as SAP or Oracle.

A 7.5 CGPA was described as an important placement threshold because many newer companies require at least 7.5 for eligibility.
